# 03_scenario_evaluator — Portfolio Trajectory Scenario Evaluator

## Overview

This module evaluates the performance of all portfolio trajectories generated in step 02. For each CVaR glidepath curve, it takes the weight tensor produced by the Hit-and-Run sampler and simulates how each portfolio trajectory would have performed over the full investment horizon under many independent return scenarios.

The output is one HDF5 file per curve containing the annualized cumulative return of every portfolio trajectory under every scenario seed. These results are used in subsequent steps to compare and rank glidepath strategies.

## What is a Scenario Seed?

The asset return matrix used in this module is a fixed, deterministic simulation (same as in step 02). A scenario seed does not re-simulate returns from scratch. Instead, it controls which of the pre-simulated return scenarios is selected for each month.

For each month in the horizon, there are `N_TRAJ` available return scenarios. A scenario seed draws one scenario index per month, forming a single realized path of market conditions across all `HORIZON_MONTHS` months. Running many seeds produces a distribution of outcomes that reflects the uncertainty in which specific scenario materializes each month.

## What is the Portfolio Shuffle?

The Hit-and-Run algorithm produces portfolios that are autocorrelated within each month: consecutive portfolios are similar because each is generated by taking a small step from the previous one. If left unshuffled, the trajectory formed by position `i` across all months would be correlated with the trajectory at position `i+1`, which is not desirable for independent evaluation.

Before evaluating, the module independently shuffles the portfolio order within each month using a fixed `SHUFFLE_SEED`. After shuffling, the trajectory at position `i` in month `t` is uncorrelated with the trajectory at position `i` in month `t+1`, because the two came from different parts of the Markov chain.

The shuffle seed is kept fixed so that the permutation is identical regardless of which scenario seeds are evaluated, ensuring that observed differences in results are attributable only to the scenario draw.

## Configuration Parameters

All configuration is defined at the top of `main.py`.

### Scenario Seeds

```python
SCENARIO_SEEDS = sorted(set([*range(1, 10001)]))
```

**What it means:** The list of seeds used to draw scenario paths. Each seed selects one return scenario per month, forming one realized path across the horizon. The module evaluates every seed independently and saves one result row per seed.

**How to modify:**
- To run a quick test: `SCENARIO_SEEDS = list(range(1, 11))` runs only 10 seeds.
- To add more seeds: extend the range or append additional values to the list.
- To resume a partial run: the output HDF5 is pre-allocated at initialization, so rerunning with a different seed range overwrites the file from scratch. There is no partial-resume mechanism.

### Shuffle Seed

```python
SHUFFLE_SEED = 42
```

**What it means:** Controls the within-month portfolio permutation applied before evaluation. Must be kept fixed across all runs to ensure that differences in results are driven only by the scenario draw. Changing this value changes which portfolio trajectory corresponds to which position index.

### Parameters That Must Match Step 02

```python
RETURNS_SEED      = 111
SIMULATION_METHOD = "copula"   # "mvn" or "copula"
N_TRAJ            = 10_000
HORIZON_MONTHS    = 480        # 480 for men (40 years), 420 for women (35 years)
```

**What they mean:** These four parameters control the asset return simulation. They must be identical to the values used in step 02. The return matrix is regenerated from scratch using these parameters, and the result must be bit-for-bit identical to the one used during sampling. Any mismatch means the CVaR constraints enforced during sampling no longer correspond to the scenarios used for evaluation.

- `RETURNS_SEED`: Random seed passed to `numpy.random.default_rng`. Determines the full return matrix.
- `SIMULATION_METHOD`: Must match step 02. `"copula"` preserves empirical marginals; `"mvn"` assumes normality.
- `N_TRAJ`: Number of return scenarios per month. Determines axis 1 of the samples matrix.
- `HORIZON_MONTHS`: Number of months in the investment horizon. Must match the weight tensors from step 02 and the glidepath curves from step 01. Set to **480** for men (retiring at 65, starting at 25) and **420** for women (retiring at 60, starting at 25).

### Curve Selection

```python
PROCESS_ALL_CURVES = True   # True = all .h5 files in hit_and_run_matrices/
CURVES_TO_PROCESS  = [f"curve_{i:04d}" for i in range(1, N+1)]  # Used only if PROCESS_ALL_CURVES = False
```

**What it means:** Controls which curves are processed in a given run.

- `PROCESS_ALL_CURVES = True`: processes every `.h5` file found in `outputs/hit_and_run_matrices/`, ignoring `CURVES_TO_PROCESS`. **This is the recommended default.**
- `PROCESS_ALL_CURVES = False`: processes only the curves listed in `CURVES_TO_PROCESS` that also have a corresponding weight file. Curves listed but not found on disk are skipped with a warning. Useful for restarting a partial run or processing a specific subset.

**How to modify:** To process a specific range, set `PROCESS_ALL_CURVES = False` and adjust the range in `CURVES_TO_PROCESS` to match the actual curves available (e.g. `range(1, 217)` for a full male run with current config).

## How It Works

### Step 1: Load historical returns and regenerate return scenarios

`returns.csv` is loaded and used to regenerate the same asset return matrix produced in step 02, using identical values of `RETURNS_SEED`, `SIMULATION_METHOD`, `N_TRAJ`, and `HORIZON_MONTHS`. The resulting `samples` array has shape `(HORIZON_MONTHS, N_TRAJ, N_ASSETS)` and is shared across all curves and all scenario seeds within the run.

### Step 2: Discover available weight files

The module scans `outputs/hit_and_run_matrices/` for files matching `curve_*.h5` and filters them against `CURVES_TO_PROCESS` (or takes all if `PROCESS_ALL_CURVES = True`).

### Step 3: For each curve

**3a. Load weight tensor.** The full tensor is loaded into memory as float64. Shape: `(HORIZON_MONTHS, N_PORTFOLIOS, N_ASSETS)`.

**3b. Shuffle within months.** Each month's portfolio order is independently permuted using `SHUFFLE_SEED`. The shuffled tensor has the same shape and values, but the portfolio index no longer carries Markov-chain autocorrelation across months.

**3c. Initialise output HDF5.** The result file is created and the `annualized_returns` dataset is pre-allocated with shape `(N_SEEDS, N_PORTFOLIOS)`.

**3d. Evaluate all scenario seeds.** The HDF5 file is opened once and all seeds are written inside the same context to avoid file-locking errors. For each seed:

1. Draw one scenario index per month uniformly from `{0, ..., N_TRAJ - 1}`, shape `(HORIZON_MONTHS,)`.
2. Select the corresponding asset returns for each month, shape `(HORIZON_MONTHS, N_ASSETS)`.
3. Compute monthly portfolio returns for all portfolios simultaneously using `einsum`, shape `(HORIZON_MONTHS, N_PORTFOLIOS)`.
4. Compute cumulative product across months, then annualize: `(1 + cumulative)^(12/T) - 1`, shape `(N_PORTFOLIOS,)`.
5. Write the result as one row in the output dataset.

## Output Files

**Location:** `outputs/scenario_results/`

**One file per curve:** `curve_0001.h5`, `curve_0002.h5`, ...

**HDF5 structure:**

Each file contains a single dataset named `annualized_returns`:

```
annualized_returns  →  shape (N_SEEDS, N_PORTFOLIOS)
                        dtype float32
```

- **Axis 0 (seeds):** Each row corresponds to one scenario seed. The seed list is stored in the attributes.
- **Axis 1 (portfolios):** Each column corresponds to one portfolio trajectory. The index matches the shuffled (not original) portfolio order.

**Metadata attributes** stored on the `annualized_returns` dataset:

| Attribute | Description |
|---|---|
| `curve_name` | Name of the curve (e.g., `curve_0001`) |
| `scenario_seeds` | Comma-separated list of all seeds evaluated |
| `shuffle_seed` | Seed used for within-month portfolio shuffle |
| `returns_seed` | Seed used to regenerate the asset return matrix |
| `simulation_method` | Return simulation method (`mvn` or `copula`) |
| `horizon_months` | Number of months in the investment horizon |
| `n_portfolios` | Number of portfolio trajectories per seed |

**Storage:** Values are saved as `float32` with gzip compression level 4. Files are chunked by seed row (`chunks = (1, N_PORTFOLIOS)`) so individual seeds can be read without loading the full matrix.

## Seed Consistency Requirements

This module shares two parameters with step 02 that must remain identical:

| Parameter | Step 02 | Step 03 | Effect if mismatched |
|---|---|---|---|
| `RETURNS_SEED` | 111 | 111 | Different return matrix; CVaR constraints invalid |
| `SIMULATION_METHOD` | copula | copula | Different return distribution; results inconsistent |
| `N_TRAJ` | 10_000 | 10_000 | Different scenario count; index selection breaks |
| `HORIZON_MONTHS` | 480 | 480 | Shape mismatch; module will crash |

`SHUFFLE_SEED` and `SCENARIO_SEEDS` are exclusive to this module and do not need to match anything in step 02.
