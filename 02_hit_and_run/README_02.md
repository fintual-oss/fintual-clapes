# 02_hit_and_run — CVaR-Constrained Portfolio Weight Sampler

## Overview

This module generates random portfolio weight tensors for each CVaR glidepath curve produced in step 01. For every curve and every month in the investment horizon, it samples portfolios whose CVaR is strictly below the glidepath limit for that month.

The output is one HDF5 file per curve, containing a three-dimensional tensor of portfolio weights. These weight tensors are consumed by step 03 to simulate portfolio trajectories.

## What is the Hit-and-Run Algorithm?

Hit-and-Run is a Markov Chain Monte Carlo (MCMC) method for sampling uniformly from a constrained region. In this module, the feasible region is the set of portfolios that simultaneously satisfy:

1. **Budget constraint**: weights sum to 1
2. **No short-selling**: all weights are non-negative
3. **CVaR constraint**: CVaR(w) < target limit for the current month

The algorithm works as follows:

1. Start from a feasible portfolio (one that already satisfies all constraints)
2. Choose a random direction in weight space
3. Find the segment of that line that stays inside the feasible region
4. Move to a random point along that segment
5. Repeat, discarding the first `burn_in` steps to reduce dependence on the starting point

Because the CVaR constraint defines a convex region, the chain converges to a uniform distribution over all valid portfolios.

## Configuration Parameters

All configuration is defined at the top of `main.py`. Edit this section to change the module's behaviour.

### Simulation Method

```python
SIMULATION_METHOD = "copula"  # "mvn" or "copula"
```

**What it means:** Controls how future asset returns are simulated for CVaR evaluation.

- `"mvn"`: Multivariate Normal. Uses estimated mean vector `mu` and covariance matrix `Sigma`. Fast and simple, but assumes returns are normally distributed.
- `"copula"`: Gaussian Copula. Preserves the empirical marginal distribution of each asset while modelling dependence via a Gaussian copula. Better captures tail behaviour and asymmetries in historical data.

**Which to use:** `"copula"` is recommended when the historical return series show skewness, fat tails, or asymmetric dependence between assets. `"mvn"` is sufficient for quick tests or when the return series are approximately normal.

### CVaR Confidence Level

```python
ALPHA_CVAR = 0.90  # CVaR confidence level (0.90 = worst 10% tail)
```

**What it means:** The confidence level used to compute CVaR. With `ALPHA_CVAR = 0.90`, CVaR is the expected loss in the worst 10% of scenarios. The internal confidence parameter passed to the sampler is `1 - ALPHA_CVAR`.

**Constraint:** Must be in (0, 1). Must match the confidence level used in step 03 to ensure consistency.

### Portfolio Generation

```python
N_PORTFOLIOS_PER_MONTH = 10_000  # Portfolios generated per month
N_TRAJ         = 10_000          # Monte Carlo scenarios for CVaR evaluation
HORIZON_MONTHS = 480             # Investment horizon in months (e.g. 480 = 40 years for men)
```

**What they mean:**

- `N_PORTFOLIOS_PER_MONTH`: Number of valid portfolios to sample for each month of each curve. Higher values give denser coverage of the feasible region but increase runtime and file size.
- `N_TRAJ`: Number of Monte Carlo scenarios used to evaluate CVaR during sampling. Higher values give more accurate CVaR estimates. Must be at least 100.
- `HORIZON_MONTHS`: Total number of months in the investment horizon. Must match the number of monthly rows in the glidepath curves from step 01. Typical values: **480** for men (40 years, retiring at 65), **420** for women (35 years, retiring at 60).

### Random Seeds

```python
RETURNS_SEED = 111  # Seed for simulated returns — must match module 03
HIT_RUN_SEED = 222  # Seed for Hit-and-Run directions
```

**What they mean:**

- `RETURNS_SEED`: Controls the random generation of the asset return scenarios used for CVaR evaluation. **This seed must be identical in step 03**, which regenerates the same return matrix to evaluate portfolio performance consistently.
- `HIT_RUN_SEED`: Controls the random directions used by the Hit-and-Run algorithm. Each curve derives its own per-month seeds deterministically from this base seed, so results are fully reproducible.

### Curve Selection

```python
CURVE_START = None  # First curve to process (None = start from the beginning)
CURVE_END   = None  # Last curve to process (None = process until the end)
```

**What it means:** Allows processing a subset of curves. Useful for restarting an interrupted run or distributing work across machines. Curves are identified by name as they appear in `glidepaths_universe.xlsx`.

- Set both to `None` to process all curves.
- Set `CURVE_START` to resume from a specific curve after a crash (e.g. `"curve_0153"`).
- Set both to process a specific range.

### Parallelization

```python
N_PROCESSES = 15  # Number of CPU processes. Set to 1 for sequential.
```

**What it means:** Each month within a curve is processed independently and can run in parallel. Setting `N_PROCESSES = 1` runs sequentially (useful for debugging). Set to `cpu_count() - 1` to use all available cores.

**Note:** Parallelism is across months within a curve, not across curves. Curves are always processed one at a time to keep memory usage predictable.

## How It Works

### Step 1: Load and prepare historical returns

`returns.csv` is loaded and used to estimate the mean vector `mu` and covariance matrix `Sigma`. `make_psd.py` corrects `Sigma` to be positive semi-definite by clipping negative eigenvalues to a small positive value (`eps = 1e-12`). This is a numerical safeguard that has no practical effect when the historical series is long enough.

### Step 2: Simulate asset returns

`simulate_asset_returns.py` generates a single return matrix of shape `(HORIZON_MONTHS, N_TRAJ, N_ASSETS)` using `RETURNS_SEED`. This matrix is shared across all curves and all months within a run. It represents the Monte Carlo scenarios used to evaluate CVaR at each step of the Hit-and-Run algorithm.

The same matrix is regenerated in step 03 using the same seed to ensure that CVaR values computed during sampling are consistent with those computed during trajectory simulation.

### Step 3: Load glidepath curves

`loaders.py` reads `glidepaths_universe.xlsx` and returns two DataFrames: one with curve parameters (`t_start`, `t_A`, `A`, `B`, `t_B`, `t_end`) and one with the monthly CVaR limits (shape: `HORIZON_MONTHS × n_curves`).

### Step 4: Sample portfolios curve by curve

For each curve, the module:

1. Reads the CVaR limit for each month from the glidepath.
2. Initialises an HDF5 file pre-allocated with shape `(HORIZON_MONTHS, N_PORTFOLIOS_PER_MONTH, N_ASSETS)`.
3. Dispatches one job per month to the process pool.
4. Each job runs the Hit-and-Run sampler (`cvar_portfolio_sampler.py`) using the return scenarios for that month and the CVaR limit for that month.
5. Writes the resulting weight matrix for that month into the HDF5 file.

If sampling fails for a month (e.g., the CVaR limit is too tight and no feasible portfolio exists), that month's slice is filled with `NaN` and a warning is printed.

## Output Files

**Location:** `outputs/hit_and_run_matrices/`

**One file per curve:** `curve_0001.h5`, `curve_0002.h5`, ...

**HDF5 structure:**

Each file contains a single dataset named `weights`:

```
weights  →  shape (HORIZON_MONTHS, N_PORTFOLIOS_PER_MONTH, N_ASSETS)
            dtype float32
```

- **Axis 0 (months):** Each slice `weights[t, :, :]` contains all portfolios generated for month `t`.
- **Axis 1 (portfolios):** Each row is one portfolio. Rows sum to 1 and all values are non-negative.
- **Axis 2 (assets):** Asset weights in the same order as the columns of `returns.csv`.

Rows containing `NaN` indicate months where sampling failed.

**Metadata attributes** stored on the `weights` dataset:

| Attribute | Description |
|---|---|
| `curve_name` | Name of the curve (e.g., `curve_0001`) |
| `horizon_months` | Number of months in the horizon |
| `n_portfolios` | Number of portfolios per month |
| `n_assets` | Number of assets |
| `returns_seed` | Seed used to generate the return scenarios |
| `hit_run_seed` | Base seed used for Hit-and-Run directions |
| `simulation_method` | Return simulation method (`mvn` or `copula`) |
| `alpha_cvar` | CVaR confidence level |
| `asset_names` | Comma-separated asset names |

**Storage:** Weights are saved as `float32` (half the size of `float64`) with gzip compression level 4. Each file is chunked by month (`chunks = (1, N_PORTFOLIOS, N_ASSETS)`) so individual months can be read without loading the full tensor.
